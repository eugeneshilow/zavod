# reels — сборка вертикальных роликов

Как из текста и картинок без человека получается файл, готовый к выкладке
в Instagram Reels: 1080×1920, MP4 H.264 + AAC, 30 кадров в секунду.

Три рельсы, одна общая концовка. **Серия** — список пунктов, который
превращается в слайды типографикой (гипотеза Г2 из
[среза рефов](research/reels-refs-2026-09-20.md)). **Плакат** — одна картинка
и одна строка поверх неё (гипотеза Г3). **История** — закадровый голос, кадр
под каждую фразу и по одному слову на экране (форма донора «Новостной Гусь»).
Все три рельсы собирают кадры и отдают их ffmpeg, который выдаёт один файл.

## Серия

Серия — один файл `content/reels/series/<id>.json`. Один файл — один ролик.

| поле                                         | что это                                                         |
| -------------------------------------------- | --------------------------------------------------------------- |
| `id`                                         | имя файла на выходе: `out/reels/<id>.mp4`. Латиница, дефисы     |
| `kicker`                                     | строка над заголовком, одна на всю серию, печатается капсом     |
| `colors.bg` · `colors.ink` · `colors.accent` | три цвета серии: фон, текст, номер. Один цвет фона на всю серию |
| `cover.title` · `cover.sub`                  | обложка: крупный заголовок и подзаголовок                       |
| `items[]`                                    | пункты: `n` (номер строкой, «01»), `title`, `text`              |
| `outro.title` · `outro.sub`                  | финал: заголовок и подзаголовок                                 |

Слайдов получается `items.length + 2`: обложка, пункты по порядку, финал.

Лекало слайда — `content/reels/template.html`: вся вёрстка и все размеры
живут там и только там. Рендер берёт из лекала блок `<style>` как есть и
подставляет данные; менять дизайн можно только правкой лекала. Что где на
слайде:

- **обложка** — кикер, заголовок крупнее обычного (класс `cover`),
  подзаголовок; номера нет;
- **пункт** — кикер, номер акцентным цветом, заголовок, абзац;
- **финал** — заголовок и подзаголовок; ни кикера, ни номера.

Подвал одинаков везде: `vibecoding.tech` слева, точки прогресса справа — по
точке на пункт. На обложке не горит ни одна, на пункте горят пройденные,
включая текущий, на финале горят все.

## Как собирается ролик

1. Playwright (chromium) открывает лекало с подставленными данными в окне
   1080×1920 и снимает каждый слайд в PNG: `out/reels/<id>/frames/NNN.png`.
2. ffmpeg склеивает кадры в видео.

Тайминг задан в одном месте — `scripts/reels/lib.mjs`:

| слайд                            | на экране                   |
| -------------------------------- | --------------------------- |
| обложка                          | 3.0 с                       |
| пункт                            | 3.4 с                       |
| финал                            | 3.0 с                       |
| переход между соседними слайдами | 0.35 с, кроссфейд (`xfade`) |

Кроссфейд ест по 0.35 с на каждом стыке, поэтому длительность ролика:

```
3.0 + N × 3.4 + 3.0 − (N + 1) × 0.35
```

где `N` — число пунктов. Для семи пунктов это 27.0 с, для пяти — 20.9 с.
Формула живёт в коде функцией `timeline()`; тест держит её на семи пунктах.

Кодирование: 30 кадров в секунду, `libx264`, `crf 20`, `yuv420p`,
`+faststart` (моov-атом в начале файла — требование Instagram).

## Плакат

Плакат — один файл `content/reels/posters/<id>.json`: `{"id", "image", "line"}`,
где `image` — путь к картинке 1024×1536 относительно корня репозитория, `line` —
одна строка текста.

Кадр 1080×1920 собирается так: фон — та же картинка, растянутая на весь кадр,
размытая и затемнённая на 25 %; поверх — та же картинка по ширине 1080 по
центру; в нижней трети — одна строка белым, 64 px, с лёгкой тенью; безопасные
поля 96 px со всех сторон. Дальше ffmpeg даёт медленный наезд 1.00 → 1.06 за
8 секунд (`zoompan`), 30 кадров в секунду. Длительность плаката — 8 с.

## История

История — один файл `content/reels/stories/<id>.json`. Закадровый голос читает
текст, картинка меняется под каждую фразу, на экране по одному слову в такт
речи. Лица в кадре нет. Форма снята с донора «Новостной Гусь»
([формула](research/2026-09-20-gus-formula/README.md)): заголовок-загадка ·
первая фраза — герой и ситуация · тело — механика «почему так» с поворотом ·
финал — последствие или ирония · без призывов.

**Ролик истории — до 60 секунд.** Столько же у донора, и столько принимает
YouTube Shorts. Ориентир при письме — 105–110 слов текста: в потоке без пауз
(раздел ниже) наш темп даёт около 150 слов в минуту, и сто с небольшим слов
укладываются секунд в сорок пять — с запасом. Длиннее вышло — режут текст, а
не ускоряют голос. Рендер не падает на длинном ролике, но пишет о нём
предупреждением в отчёт.

| поле              | что это                                                                                                                                                                                                                                                  |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`              | имя файла на выходе: `out/reels/<id>.mp4`                                                                                                                                                                                                                |
| `title`           | заголовок для подписи и отчёта, 2–5 слов                                                                                                                                                                                                                 |
| `voice`           | голос трёх движков: `eleven:<voice_id>` — ElevenLabs v3 с эмоциональными тегами, `eleven:<voice_id>:v2` — ElevenLabs Multilingual v2, `yandex:<голос>[:<амплуа>]` — SpeechKit (напр. `yandex:alexander:good`), `say:<имя>` — встроенный в macOS черновик |
| `speed`           | скорость чтения: у SpeechKit и у `eleven:…:v2` — параметр запроса, у `eleven:` v3 — `atempo` по готовой дорожке целиком, 0.85–1.15, высота не меняется. 1.0 — спокойный рассказчик, 1.3 — темп донора. По умолчанию 1.1                                  |
| `flow`            | как сшиты биты в речи: `continuous` — без пауз, по донору (по умолчанию), `paused` — прежняя пауза между битами. Раздел «Поток без пауз» ниже                                                                                                            |
| `stability`       | насколько ровно читает ElevenLabs: 0 — живая игра голосом, 1 — ровное чтение. Ниже 0.3 движок слушается тегов и знаков, выше 0.6 их почти не замечает. От 0 до 1, по умолчанию 0.55; уровень канала — 0.25, раздел «Уровень экспрессии канала» ниже      |
| `beats[]`         | биты истории по порядку: `text` — одна-три фразы, `visual` — что на экране, пока они звучат                                                                                                                                                              |
| `say` в бите      | необязательный текст ДЛЯ ГОЛОСА, когда он отличается от экранного: числа и латиница словами. На экране остаётся `text`                                                                                                                                   |
| разметка в `text` | пауза `sil<[300]>`, ударение `**слово**` (SpeechKit) и аудио-теги `[thoughtful]` (ElevenLabs) — их слышит голос, но не видит зритель                                                                                                                     |
| `music`           | путь к треку из `assets/music/` или пусто                                                                                                                                                                                                                |

`visual` бывает четырёх видов: `{"kind":"image","src":"…"}` — картинка с
медленным наездом; `{"kind":"video","src":"…","from":сек,"crop":"w:h:x:y"}` —
кусок видео (кроп берётся из кадра, обрезается по центру до 9:16 и заполняет
кадр целиком — ни подложки, ни полей, а центральная обрезка срезает чужие
подписи по углам); `{"kind":"card","big":"97 из 100","small":"команд робот попытался
выполнить"}` — типографская карточка с цифрой по лекалу серии;
`{"kind":"tweet","name":"Elon Musk","handle":"@elonmusk","text":"Sounds
bad","meta":"7,4 млн просмотров · 19.09.2026"}` — карточка поста, нарисованная
нами (скриншоты чужих экранов не делаем). Картинки и видео лежат в
`content/reels/media/<id>/` и каждая имеет строку в
`content/reels/media/LICENSES.md`: `файл · источник (URL) · лицензия · дата`.
Файл без строки в ролик не идёт.

### Голоса канала

Два голоса ElevenLabs, оба на модели v3, оба из библиотеки — на них нужен план
Starter и выше:

| id                     | голос                                 | где                     |
| ---------------------- | ------------------------------------- | ----------------------- |
| `ogi2DyUAKJb7CEdqqvlU` | Stanislav — Deep, Empathetic and Warm | основной голос историй  |
| `6A9D8WSMm4rFsg2DWFeE` | Egor Gadzhiyev — Clear and Commanding | второй голос, для пробы |

В файле истории это строка `"voice": "eleven:ogi2DyUAKJb7CEdqqvlU"`, а послушать
второй на том же тексте можно флагом, не трогая файл:
`--voice eleven:6A9D8WSMm4rFsg2DWFeE`. Встроенные голоса ElevenLabs
(`category: premade`) работают на любом тарифе и годятся как черновик, но они
все англоязычные.

### Разметка для голоса

Голосу уходит не тот текст, что зрителю. Зритель всегда видит `text`,
очищенный от всякой разметки. Голос читает `say`, если он есть в бите, иначе
`text` — и читает его со своей разметкой. Что с чем происходит:

| разметка                  | ElevenLabs                                   | SpeechKit и `say` | на экране       |
| ------------------------- | -------------------------------------------- | ----------------- | --------------- |
| `sil<[300]>`              | превращается в многоточие `...`              | уходит как есть   | снята           |
| `**слово**`               | превращается в `слово`: ударений v3 не знает | уходит как есть   | звёздочки сняты |
| `[thoughtful]`, `[pause]` | уходят как есть — это аудио-теги             | вырезаны          | снята           |
| `...`                     | пауза и вес фразы                            | уходит как есть   | одна точка      |

У ElevenLabs числа и латиницу **всегда пишут словами в `say`**: «девяносто
семь», «Джи-пи-ти шесть Астра», «Саундс бэд». Цифру «97» и латиницу «GPT-6»
движок на русском читает по-своему, и предсказать это нельзя. Пауза — не
больше одной на бит, и стоит она перед поворотом истории. Какие теги ставить и
насколько ровно читать — ниже.

#### Уровень экспрессии канала

Голос канала играет, а не читает ровно. Умолчание новой истории — `stability`
**0.25**: на этом уровне движок слышит теги и знаки препинания, выше 0.6 он их
почти не замечает, а ниже 0.2 два прогона одного текста расходятся между собой.

Теги ставят по рецепту жанра, **не больше одного на бит**:

- первый бит открывается `[dramatic, animated narrator]` — он задаёт тон всему
  ролику;
- перечисление помечается `[listing fast]`;
- поворот истории — `[beat]` перед короткой фразой;
- тревожный вывод — `[ominous]`, цитата — `[quietly]`;
- финал — `[sighs]` или `[amused]`.

Теги берут **только из списка, который ElevenLabs называет сам** в доках и
блоге v3: `dramatic`, `animated`, `excited`, `ominous`, `quietly`, `whispers`,
`sighs`, `beat`, `listing fast`, `intrigued`, `amused`. Выдуманный тег движок
либо не слышит, либо читает вслух. Смех жанр ломает
([срез про голос](research/2026-09-21-viral-voice/README.md)).

В тексте для голоса (`say`) разрешены `!` и `:`: восклицательный знак поднимает
голос к концу фразы, двоеточие держит её открытой перед перечислением. На
экране (`text`) знаки остаются как в прозе — зритель читает текст, а не
партитуру.

### Поток без пауз (по донору)

У донора «Новостной Гусь» пауз между фразами нет вовсе: он тянет последнюю
букву предыдущего предложения в первую букву следующего. У нас пауз было три
слоя — пустая строка между битами в тексте для голоса, точка в конце каждой
фразы и сам движок. Поэтому у истории есть поле `flow` с двумя значениями.

- `continuous` — по донору, **и это значение по умолчанию** у новой истории.
- `paused` — как было: пустая строка между битами, точки на местах. Ничего из
  написанного ниже к такой истории не применяется.

В режиме `continuous` работают два слоя.

**Первый слой — текст.** Биты для голоса склеиваются **одним пробелом**, а не
пустой строкой. Точка в конце бита для голоса заменяется на запятую — потому
что точка для движка команда «остановись», а запятая «продолжай». Точка
остаётся на месте у последнего бита и у битов, чей текст кончается на `?` или
`!`: там пауза и есть смысл фразы. Многоточия `...` и теги `[thoughtful]`
внутри бита не трогаются никогда — это явное решение автора, а не случайная
точка. Зритель ничего из этого не видит: на экране всегда `text` бита.

Слово перед стыком можно **растянуть руками** — двойной или тройной гласной,
удвоенной согласной: «это тесст», «похожей на человекааа». Растяжка пишется
только в `say` бита и только там, где её хочет автор; автоматически её не
ставит никто.

**Второй слой — сведение.** После синтеза, до `atempo`, в готовой дорожке
ищутся куски тишины, и всё, что длиннее `maxGap` (по умолчанию 0.12 с),
вырезается: от куска остаётся ровно `maxGap`. Шов склеивается кроссфейдом
40 мс, чтобы не было щелчка. Таймкоды символов и слов сдвигаются на ту же
вырезанную длину — **иначе субтитры уедут вперёд речи ровно на столько, сколько
вырезали**. Сведение живёт на выходе, рядом с `atempo`: в кеше лежит звук до
него, поэтому подбор `maxGap` не стоит ни одного кредита.

Край честный: **полностью убрать паузы v3 не даёт** — движок сам ставит дыхание
и добор воздуха там, где считает нужным. Текст снимает большую часть, остаток
добирает сведение. Отчёт рендера печатает обе цифры: сколько пауз было и стало,
и сколько секунд вырезано.

Второй край: `flow` действует на пути ElevenLabs, где вся история едет одним
куском. У SpeechKit и `say` биты озвучиваются отдельными запросами, и границы
битов берутся из длины звука каждого — вырезать из такой дорожки тишину значит
сломать границы. Такая история читается с паузами, каким бы ни был `flow`.

### Как собирается звук: у ElevenLabs — одним куском

**Вся история озвучивается ОДНИМ запросом.** Тексты битов для голоса
склеиваются в один текст, а чем именно — решает `flow`: при `continuous` это
один пробел, при `paused` — перевод строки и пустая строка (у v3 это пауза);
правила режима — в разделе «Поток без пауз» выше. Запрос идёт на
`POST /v1/text-to-speech/<voice_id>/with-timestamps`
(тело то же: `text`, `model_id`, `language_code`, `voice_settings`), и ответ
приходит JSON'ом: `audio_base64` и `alignment` — время начала и конца **каждого
символа** текста. Почему так: запрос на каждый бит отдельно движок читает с
нуля, и на швах прыгают интонация и тон — «каждая реплика идёт как будто бы
новым голосом».

Из этих таймкодов берётся всё: границы бита — от первого до последнего
звучащего символа его куска, время слова — от первого до последнего символа
слова. Распознавание на этом пути не участвует вовсе, `whisper` для
ElevenLabs не зовут. Отрезки аудио-тегов `[…]` выбрасываются: они не звучат.
На экране всегда слова `text` бита, а с временами `say`-текста они
сопоставляются по счёту слов внутри бита — тем же порядком, только теперь по
честным временам символов, а не по долям.

Скорость у v3 правит `atempo` по всей готовой дорожке целиком, и времена
таймкодов делятся на тот же коэффициент; перед ним, если `flow: continuous`,
дорожку проходит сведение пауз. Кеш один на всю историю: ключ — весь
текст для голоса, голос, модель и stability; рядом со звуком лежат и таймкоды,
поэтому пересборка не стоит ничего, а правка одного бита переозвучивает историю
целиком. **Скорости у v3 в ключе нет**: в кеше лежит звук ДО темпа, `atempo`
применяется на выходе — значит подбор скорости бесплатен, хоть десять раз
подряд. У `eleven:…:v2` скорость едет параметром запроса, и в ключ она входит.

Сценарий длиннее 4500 знаков режется на куски **по границам битов**, и каждый
кусок идёт с `previous_text` и `next_text` — текстами соседних кусков. Это
запасной путь: шов между кусками слышен так же, как раньше слышались швы
между битами.

### Как собирается звук: у SpeechKit и `say` — по битам

1. Текст озвучивается **по битам** — отдельный запрос на каждый бит; бит
   длиннее предела куска режется по концам фраз и склеивается звуком внутри себя,
   а готовый звук бита лежит в `out/reels/<id>/voice/<ключ>.wav`, где ключ — текст
   для голоса, сам голос, модель, stability и скорость: переозвучивается только
   изменившийся бит. 2) Биты склеиваются в `out/reels/<id>/voice.wav` через
   **0.25 с тишины** между соседними, и **границы битов берутся из точной длины
   звука каждого бита**, а не из распознавания. 3) Время слов внутри бита уточняет
   `whisper-cli` с `-ml 1 -sow`, запущенный на звуке этого бита отдельно — его
   слова берутся, только если он услышал в куске столько же слов, сколько в тексте
   бита (±1), ни одно не нулевой длины и времена не убывают; иначе слова
   раскладываются пропорционально числу букв, а слово с точкой или запятой на конце
   получает лишние 0.15 с.

### Дальше — общее для всех трёх голосов

Слова заполняют границы бита целиком, времена строго возрастают, ни одно слово
не короче 0.12 с; таблица границ пишется в `out/reels/<id>/beats.json`. Каждый
`visual` рендерится в клип своей длительности (Playwright для карточек, ffmpeg
для картинок и видео), клипы склеиваются встык без кроссфейда, а карточка дольше
3 секунд не стоит статично — едет тем же медленным наездом, что у плаката.
Субтитры — файл `.ass`, одно слово на событие, Arial Bold 116 px, белый с
чёрной обводкой 8 px и лёгкой тенью, на 62 % высоты кадра; одиночное тире не
слово и на экран не идёт; водяной знак `vibecoding.ru` — 34 px, белый на 70 %,
внизу с полем 96 px. Голос микшируется с музыкой, музыка на −14 dB под
голосом, затухание 1,5 с; кодирование — как у серии. Темп речи донора —
160 слов в минуту; `say -r 170`.

Отчёт рендера пишет длительность, число битов, слов в минуту и
`voice: say|yandex|eleven` с моделью. У истории в режиме `continuous` туда же
идёт строка сведения: сколько пауз длиннее 0.15 с было и стало и сколько секунд
вырезано. Ролик на встроенном голосе — черновик:
перед выкладкой озвучить живым движком.

## Музыка

Звуковая дорожка обязательна: Instagram не принимает файл без аудио. Поэтому
у рендера два режима, и оба дают дорожку.

- **С треком.** Флаг `--music assets/music/<файл>.mp3`. Трек обрезается по
  длине видео, последние 1.5 секунды — затухание. Кодек AAC 160 kbps, 48 kHz.
- **Без трека.** Дорожка тишины, тот же AAC. Файл технически годен к выкладке,
  но ролик считается черновиком: рендер пишет в отчёт строку
  `audio: silent` — это значит, что перед выкладкой нужно добавить музыку.

Треки живут в `assets/music/*.mp3`. Туда кладут только royalty-free музыку,
которую разрешено вшивать в файл, — например с Pixabay. Музыку из библиотеки
Instagram (Meta Sound Collection) вшивать нельзя: её лицензия действует только
внутри продуктов Meta; такой трек прикрепляется при публикации через API
(`audio_configuration`), а не в файле. Подробности и проверенные ссылки —
в [срезе про музыку](research/music-and-formats-2026-09-20.md).

На каждый трек в папке — строка в `assets/music/LICENSES.md`:

```
название · автор · источник (URL) · лицензия · дата добавления
```

Трек без строки в этом файле считается неизвестного происхождения и в ролик
не идёт.

## Требования к файлу для Instagram

Из справочника Meta for Developers (проверено 20.09.2026, цитаты — в
[срезе](research/music-and-formats-2026-09-20.md)). Наши значения — справа.

| требование                                  | наше значение                              |
| ------------------------------------------- | ------------------------------------------ |
| контейнер MP4, moov-атом в начале           | MP4, `-movflags +faststart`                |
| видео H.264, прогрессивная развёртка, 4:2:0 | `libx264`, `yuv420p`                       |
| аудио AAC, до 48 kHz, 1–2 канала            | AAC 160 kbps, 48 kHz, стерео               |
| 23–60 кадров в секунду                      | 30                                         |
| соотношение сторон — рекомендовано 9:16     | 1080×1920                                  |
| длительность от 3 секунд                    | серия 20–30 с, плакат 8 с, история до 60 с |
| размер файла до 300 МБ                      | десятки мегабайт                           |

Верхняя граница длины у Meta — 15 минут, но по замерам охвата держим ролик
короче 60 секунд: столько же принимает YouTube Shorts, и столько у донора.

## Команды

```
pnpm reels                                   # все серии и все плакаты
node scripts/reels/render-slides.mjs content/reels/series/<id>.json
node scripts/reels/render-slides.mjs content/reels/series/<id>.json --music assets/music/<файл>.mp3
node scripts/reels/render-poster.mjs <картинка.png> --line "текст"
node scripts/reels/render-story.mjs content/reels/stories/<id>.json
node scripts/reels/render-story.mjs content/reels/stories/<id>.json --voice yandex:filipp
node scripts/reels/render-story.mjs content/reels/stories/<id>.json --voice eleven:6A9D8WSMm4rFsg2DWFeE
```

Флаги всех трёх рендеров: `--music <путь>` — трек; `--out <путь>` — куда
положить файл (по умолчанию `out/reels/<id>.mp4`). У истории есть свой флаг
`--voice say:<голос>|yandex:<голос>|eleven:<voice_id>` — он перебивает поле
`voice` файла истории.

Что нужно на машине: ffmpeg (`brew install ffmpeg`) и браузер Playwright
(`npx playwright install chromium` после `pnpm install`). Сам `playwright` —
зависимость разработки, в продакшен-сборку не попадает.

## Где лежат выходы

`out/` целиком вне git: готовые файлы и кадры — результат, а не истина. Внутри
`out/reels/` лежат `<id>.mp4` и папка `<id>/frames/` с кадрами. Кадры остаются
на диске: по ним видно, что именно ушло в ролик, и пересборка без Playwright
делается только ffmpeg.

## Раннер идей

Владелец кладёт мысль в лоток на экране сети
([social/instagram.md](social/instagram.md), «Лоток идей»), а раннер на маке Pro
делает из неё ролик без человека. Раз в десять минут он берёт из лотка самую
старую идею, пишет по ней историю подписочным Claude по рецепту мозга
`short-videos`, собирает ролик и ставит его в очередь публикации. Идея в лотке
получает статус «готово» и имя истории; сама история остаётся в её строке и в
`out/ideas/<имя>.json`.

Первая версия делает кадры только двух видов — карточка с цифрой и карточка
поста. Чужие видео и картинки раннер не берёт: на каждый файл нужна строка в
`content/reels/media/LICENSES.md` и ручная выкачка, а лицензию машина себе не
выпишет.

```
node scripts/reels/idea-runner.mjs                                      # один тик
node scripts/reels/idea-runner.mjs --dry-run "<текст идеи>"             # без лотка и эфира
node scripts/reels/idea-runner.mjs --dry-run --no-render "<текст идеи>" # только история
```

Сухой прогон лоток не трогает и в эфир ничего не ставит: пишет историю в
`out/ideas/dry-<имя>.json`, собирает ролик рядом и печатает путь, слова, секунды
и время шагов.

Тик ставит launchd — `scripts/launchd/ru.vibecoding.zavod-idea-runner.plist`;
установка, остановка (`launchctl unload …`) и переменные — в шапке самого файла.
Лог: `~/Library/Logs/zavod-idea-runner.log`, время московское. Два тика разом не
идут: замок `out/ideas/.lock` держит номер живого процесса.

Края раннера:

- Историю пишет отдельный профиль подписки Claude (`IDEA_RUNNER_PROFILE`, по
  умолчанию `jvshilov`). Профиль отключён или просрочен — история не пишется, и
  идея уходит в «не вышло» с этой причиной.
- Раннер умер с идеей в работе — следующий тик через два часа вернёт её со
  статусом «не вышло: зависла в работе больше двух часов».
- Идеи и очередь публикации живут в прод-деплое: адрес и пропуск раннер
  спрашивает у самого Convex (`npx convex env get … --prod`), поэтому на маке
  нужен вход в Convex.
- Историю проверяют до рендера: разбор теми же правилами, что у рендера, кадры
  только свои, 90–120 слов, 8–20 битов, подпись поста до 300 знаков. Не прошло —
  одна повторная попытка с причиной отказа, потом «не вышло».

## Известные края

- Шрифт Inter на машине может отсутствовать; лекало падает на системный
  Helvetica Neue. Шрифты рендер не качает.
- Playwright снимает окно целиком, не элемент: слайд ровно 1080×1920 и в окно
  влезает полностью.
- Выкладки в этой зоне нет: рельса кончается файлом на диске. Дальше файл
  забирает очередь публикации — [publish.md](publish.md).
- Субтитры истории вжигает `libass`, а сборка ffmpeg из Homebrew бывает без
  него. Рендер сам ищет ffmpeg, у которого есть фильтр `ass`: сначала `ffmpeg`
  из PATH, затем `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`, затем путь из
  переменной `FFMPEG_ASS`. Ни одного не нашлось — рендер останавливается и
  называет, чего не хватает.
- **Дорожка звука не переписывает свои времена счётчиком сэмплов.** Фильтр
  `asetpts=N/SR/TB` рядом с видео из склейки (`-f concat`) сминает часть звука в
  одну точку: у готового файла картинка идёт 66.5 с, а звуковая дорожка
  объявляет 55.7 с, и после этого места звук расходится с картинкой. Замер на
  `robot-knife`: 505 пакетов подряд со сдвигом в один сэмпл начиная с 10.73 с.
  Поэтому у звука остаются его собственные времена: `aresample`, `apad`, `atrim`
  и ничего больше; тест держит правило.
- **`whisper.cpp` по словам ненадёжен, поэтому он только уточняет, а не задаёт**
  — и только у SpeechKit и `say`; у ElevenLabs его не зовут вовсе.
  На длинном файле с `-ml 1 -sow` часть слов схлопывается к началу своего
  сегмента и получает нулевую длину («Это 4.040–4.040»), а соседние слипаются:
  границы битов, построенные на таких временах, уезжают вперёд речи на секунды.
  Поэтому границы битов задаёт длина звука, а слова whisper берутся только
  внутри бита и только когда прошли проверку (счёт ±1, нет нулевых, времена не
  убывают). Слова текста и слова whisper к тому же расходятся на числах и
  сокращениях («7 400 000» он слышит как несколько слов) — на экране всегда
  текст истории; расхождение больше 15 % рендер пишет предупреждением в отчёт.
- Встроенный голос macOS (`say`) читает ровно и без интонации: это черновик,
  чтобы увидеть монтаж. Живой голос — SpeechKit.
- Разметка бита в субтитры не попадает никогда: правила перевода — в разделе
  «Разметка для голоса» выше, там же их дом.
- **ElevenLabs v3 не умеет регулировать скорость.** Поле `speed` истории у
  `eleven:` v3 применяется уже к готовому звуку бита фильтром `atempo` (высота
  не меняется), и только в пределах 0.85–1.15: за ними слышно, что запись
  тянут. Значение вне предела рендер подрезает до края и пишет об этом в отчёт.
  У `eleven:…:v2` скорость есть своя, параметром запроса.
- **Бесплатный план ElevenLabs не пускает голоса из библиотеки через API.**
  Ответ — 402 `paid_plan_required`; нужен план Starter и выше. Встроенные
  голоса (`category: premade`) работают и на бесплатном. Рендер показывает эту
  ошибку словами, а не стеком.
- **Сырой PCM на бесплатном плане тоже закрыт.** Рендер просит
  `output_format=pcm_48000`, а на отказ по формату повторяет запрос как
  `mp3_44100_128` и перекодирует ffmpeg в PCM 48 kHz моно — как у остальных
  голосов. В отчёт идёт строка, каким форматом вошли.
- **Кредиты ElevenLabs тратит кеш-промах, а не рендер.** Один знак текста —
  один кредит, и списывается он в момент запроса; повторная сборка того же
  ролика не стоит ничего, потому что звук и таймкоды лежат в
  `out/reels/<id>/voice/`. Но история озвучивается целиком, поэтому правка
  одного слова стоит весь сценарий: у `robot-knife` это около 1300 знаков.
  Цена ровного голоса — такая.
- **`with-timestamps` у v3 работает на плане Starter** (проверено 21.09.2026 на
  голосе Stanislav: ответ 200, `output_format=pcm_48000`, массив символов
  совпадает с отправленным текстом знак в знак, включая теги и переводы строк).
  Закроют его тарифом — запасной путь такой: обычный MP3 без таймкодов плюс
  `whisper` **по всей дорожке сразу**, а не по битам; границы битов тогда
  придётся искать по словам, и это заметно хуже.
- **Символы тегов `[…]` в таймкодах есть, хотя не звучат.** У `[calm]` в начале
  сценария свой отрезок времени в `alignment`; его выбрасывают, иначе первое
  слово на экране встанет раньше речи.
- Вход в ElevenLabs один: ключ `ELEVENLABS_API_KEY` в `.env.local`, заголовок
  `xi-api-key`. Ключ в лог и в отчёт не печатается.
- Голос идёт через REST v3 SpeechKit (`tts/v3/utteranceSynthesis`) — у v1 нет
  голосов с амплуа (`alexander`, `anton`, `kirill`): на них он отвечает
  «Unsupported voice». Ответ v3 приходит потоком строк JSON, звук лежит кусками
  в `result.audioChunk.data` и склеивается по порядку.
- В SpeechKit рендер входит двумя способами: ключ `YC_API_KEY` и `YC_FOLDER_ID`
  из `.env.local` либо, если ключа нет, живая консоль `yc` (`yc iam
create-token` и `yc config get folder-id`). Ни токен, ни ключ в лог и в отчёт
  не печатаются. Один запрос берёт кусок до 250 знаков, поэтому текст режется по концам фраз
  и склеивается обратно уже звуком.
- Переозвучить готовую историю можно одной командой: звук, карточки и клипы
  лежат в `out/reels/<id>/` с ключом и заново не считаются. У SpeechKit и `say`
  правка одного бита переозвучивает только его; у ElevenLabs — всю историю.
  Карточки и браузер не трогаются вовсе. Меняется голос или скорость —
  меняется весь звук, а с ним и клипы.
