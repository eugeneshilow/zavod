# reels — сборка вертикальных роликов

Как из текста и картинок без человека получается файл, готовый к выкладке
в Instagram Reels: 1080×1920, MP4 H.264 + AAC, 30 кадров в секунду.

Три рельсы, одна общая концовка. **Серия** — список пунктов, который
превращается в слайды типографикой (гипотеза Г2 из
[среза рефов](research/reels-refs-2026-09-20.md)). **Плакат** — одна картинка
и одна строка поверх неё (гипотеза Г3). **История** — закадровый голос, кадр
под каждую фразу и по одному слову на экране (форма донора «Новостной Гусь»).
Все три рельсы собирают кадры и отдают их ffmpeg, который выдаёт один файл.

## Серия

Серия — один файл `content/reels/series/<id>.json`. Один файл — один ролик.

| поле                                         | что это                                                         |
| -------------------------------------------- | --------------------------------------------------------------- |
| `id`                                         | имя файла на выходе: `out/reels/<id>.mp4`. Латиница, дефисы     |
| `kicker`                                     | строка над заголовком, одна на всю серию, печатается капсом     |
| `colors.bg` · `colors.ink` · `colors.accent` | три цвета серии: фон, текст, номер. Один цвет фона на всю серию |
| `cover.title` · `cover.sub`                  | обложка: крупный заголовок и подзаголовок                       |
| `items[]`                                    | пункты: `n` (номер строкой, «01»), `title`, `text`              |
| `outro.title` · `outro.sub`                  | финал: заголовок и подзаголовок                                 |

Слайдов получается `items.length + 2`: обложка, пункты по порядку, финал.

Лекало слайда — `content/reels/template.html`: вся вёрстка и все размеры
живут там и только там. Рендер берёт из лекала блок `<style>` как есть и
подставляет данные; менять дизайн можно только правкой лекала. Что где на
слайде:

- **обложка** — кикер, заголовок крупнее обычного (класс `cover`),
  подзаголовок; номера нет;
- **пункт** — кикер, номер акцентным цветом, заголовок, абзац;
- **финал** — заголовок и подзаголовок; ни кикера, ни номера.

Подвал одинаков везде: `vibecoding.tech` слева, точки прогресса справа — по
точке на пункт. На обложке не горит ни одна, на пункте горят пройденные,
включая текущий, на финале горят все.

## Как собирается ролик

1. Playwright (chromium) открывает лекало с подставленными данными в окне
   1080×1920 и снимает каждый слайд в PNG: `out/reels/<id>/frames/NNN.png`.
2. ffmpeg склеивает кадры в видео.

Тайминг задан в одном месте — `scripts/reels/lib.mjs`:

| слайд                            | на экране                   |
| -------------------------------- | --------------------------- |
| обложка                          | 3.0 с                       |
| пункт                            | 3.4 с                       |
| финал                            | 3.0 с                       |
| переход между соседними слайдами | 0.35 с, кроссфейд (`xfade`) |

Кроссфейд ест по 0.35 с на каждом стыке, поэтому длительность ролика:

```
3.0 + N × 3.4 + 3.0 − (N + 1) × 0.35
```

где `N` — число пунктов. Для семи пунктов это 27.0 с, для пяти — 20.9 с.
Формула живёт в коде функцией `timeline()`; тест держит её на семи пунктах.

Кодирование: 30 кадров в секунду, `libx264`, `crf 20`, `yuv420p`,
`+faststart` (моov-атом в начале файла — требование Instagram).

## Плакат

Плакат — один файл `content/reels/posters/<id>.json`: `{"id", "image", "line"}`,
где `image` — путь к картинке 1024×1536 относительно корня репозитория, `line` —
одна строка текста.

Кадр 1080×1920 собирается так: фон — та же картинка, растянутая на весь кадр,
размытая и затемнённая на 25 %; поверх — та же картинка по ширине 1080 по
центру; в нижней трети — одна строка белым, 64 px, с лёгкой тенью; безопасные
поля 96 px со всех сторон. Дальше ffmpeg даёт медленный наезд 1.00 → 1.06 за
8 секунд (`zoompan`), 30 кадров в секунду. Длительность плаката — 8 с.

## История

История — один файл `content/reels/stories/<id>.json`. Закадровый голос читает
текст, картинка меняется под каждую фразу, на экране по одному слову в такт
речи. Лица в кадре нет. Форма снята с донора «Новостной Гусь»
([формула](research/2026-09-20-gus-formula/README.md)): заголовок-загадка ·
первая фраза — герой и ситуация · тело — механика «почему так» с поворотом ·
финал — последствие или ирония · без призывов.

| поле      | что это                                                                                                                                      |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`      | имя файла на выходе: `out/reels/<id>.mp4`                                                                                                    |
| `title`   | заголовок для подписи и отчёта, 2–5 слов                                                                                                     |
| `voice`   | голос: `yandex:<голос>[:<амплуа>]` (SpeechKit, напр. `yandex:filipp`, `yandex:alexander:good`) или `say:<имя>` — встроенный в macOS черновик |
| `speed`   | скорость чтения у SpeechKit: 1.0 — спокойный рассказчик, 1.3 — темп донора. По умолчанию 1.1                                                 |
| `beats[]` | биты истории по порядку: `text` — одна-три фразы, `visual` — что на экране, пока они звучат                                                  |
| `music`   | путь к треку из `assets/music/` или пусто                                                                                                    |

`visual` бывает четырёх видов: `{"kind":"image","src":"…"}` — картинка с
медленным наездом; `{"kind":"video","src":"…","from":сек,"crop":"w:h:x:y"}` —
кусок видео; `{"kind":"card","big":"97 из 100","small":"команд робот попытался
выполнить"}` — типографская карточка с цифрой по лекалу серии;
`{"kind":"tweet","name":"Elon Musk","handle":"@elonmusk","text":"Sounds
bad","meta":"7,4 млн просмотров · 19.09.2026"}` — карточка поста, нарисованная
нами (скриншоты чужих экранов не делаем). Картинки и видео лежат в
`content/reels/media/<id>/` и каждая имеет строку в
`content/reels/media/LICENSES.md`: `файл · источник (URL) · лицензия · дата`.
Файл без строки в ролик не идёт.

Как собирается: 1) текст всех битов озвучивается одним куском (`say` или
SpeechKit) в `out/reels/<id>/voice.wav`; 2) `whisper-cli` с `-ml 1 -sow` даёт
время каждого слова; 3) биты получают границы по счёту слов своего текста,
длительность бита — от первого до последнего его слова; 4) каждый `visual`
рендерится в клип своей длительности (Playwright для карточек, ffmpeg для
картинок и видео), клипы склеиваются встык без кроссфейда; 5) субтитры — файл
`.ass`, одно слово на событие, Arial Bold 96 px, белый с чёрной обводкой 6 px,
нижняя треть кадра; водяной знак `vibecoding.ru` под субтитрами; 6) голос
микшируется с музыкой, музыка на −14 dB под голосом, затухание 1,5 с;
кодирование — как у серии. Темп речи донора — 160 слов в минуту; `say -r 170`.

Отчёт рендера пишет длительность, число битов, слов в минуту и
`voice: say|yandex`. Ролик на встроенном голосе — черновик: перед выкладкой
озвучить SpeechKit.

## Музыка

Звуковая дорожка обязательна: Instagram не принимает файл без аудио. Поэтому
у рендера два режима, и оба дают дорожку.

- **С треком.** Флаг `--music assets/music/<файл>.mp3`. Трек обрезается по
  длине видео, последние 1.5 секунды — затухание. Кодек AAC 160 kbps, 48 kHz.
- **Без трека.** Дорожка тишины, тот же AAC. Файл технически годен к выкладке,
  но ролик считается черновиком: рендер пишет в отчёт строку
  `audio: silent` — это значит, что перед выкладкой нужно добавить музыку.

Треки живут в `assets/music/*.mp3`. Туда кладут только royalty-free музыку,
которую разрешено вшивать в файл, — например с Pixabay. Музыку из библиотеки
Instagram (Meta Sound Collection) вшивать нельзя: её лицензия действует только
внутри продуктов Meta; такой трек прикрепляется при публикации через API
(`audio_configuration`), а не в файле. Подробности и проверенные ссылки —
в [срезе про музыку](research/music-and-formats-2026-09-20.md).

На каждый трек в папке — строка в `assets/music/LICENSES.md`:

```
название · автор · источник (URL) · лицензия · дата добавления
```

Трек без строки в этом файле считается неизвестного происхождения и в ролик
не идёт.

## Требования к файлу для Instagram

Из справочника Meta for Developers (проверено 20.09.2026, цитаты — в
[срезе](research/music-and-formats-2026-09-20.md)). Наши значения — справа.

| требование                                  | наше значение                              |
| ------------------------------------------- | ------------------------------------------ |
| контейнер MP4, moov-атом в начале           | MP4, `-movflags +faststart`                |
| видео H.264, прогрессивная развёртка, 4:2:0 | `libx264`, `yuv420p`                       |
| аудио AAC, до 48 kHz, 1–2 канала            | AAC 160 kbps, 48 kHz, стерео               |
| 23–60 кадров в секунду                      | 30                                         |
| соотношение сторон — рекомендовано 9:16     | 1080×1920                                  |
| длительность от 3 секунд                    | серия 20–30 с, плакат 8 с, история 45–90 с |
| размер файла до 300 МБ                      | десятки мегабайт                           |

Верхняя граница длины у Meta — 15 минут, но по замерам охвата держим ролик
короче 90 секунд.

## Команды

```
pnpm reels                                   # все серии и все плакаты
node scripts/reels/render-slides.mjs content/reels/series/<id>.json
node scripts/reels/render-slides.mjs content/reels/series/<id>.json --music assets/music/<файл>.mp3
node scripts/reels/render-poster.mjs <картинка.png> --line "текст"
node scripts/reels/render-story.mjs content/reels/stories/<id>.json
node scripts/reels/render-story.mjs content/reels/stories/<id>.json --voice yandex:filipp
```

Флаги всех трёх рендеров: `--music <путь>` — трек; `--out <путь>` — куда
положить файл (по умолчанию `out/reels/<id>.mp4`). У истории есть свой флаг
`--voice say:<голос>|yandex:<голос>` — он перебивает поле `voice` файла истории.

Что нужно на машине: ffmpeg (`brew install ffmpeg`) и браузер Playwright
(`npx playwright install chromium` после `pnpm install`). Сам `playwright` —
зависимость разработки, в продакшен-сборку не попадает.

## Где лежат выходы

`out/` целиком вне git: готовые файлы и кадры — результат, а не истина. Внутри
`out/reels/` лежат `<id>.mp4` и папка `<id>/frames/` с кадрами. Кадры остаются
на диске: по ним видно, что именно ушло в ролик, и пересборка без Playwright
делается только ffmpeg.

## Известные края

- Шрифт Inter на машине может отсутствовать; лекало падает на системный
  Helvetica Neue. Шрифты рендер не качает.
- Playwright снимает окно целиком, не элемент: слайд ровно 1080×1920 и в окно
  влезает полностью.
- Публикации в Instagram в этой зоне нет: рельса кончается файлом на диске.
  Выкладка через Graph API — отдельная зона, когда она появится.
- Субтитры истории вжигает `libass`, а сборка ffmpeg из Homebrew бывает без
  него. Рендер сам ищет ffmpeg, у которого есть фильтр `ass`: сначала `ffmpeg`
  из PATH, затем `/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`, затем путь из
  переменной `FFMPEG_ASS`. Ни одного не нашлось — рендер останавливается и
  называет, чего не хватает.
- Слова у whisper и слова текста расходятся на числах и сокращениях («7 400 000»
  он слышит как несколько слов). Биты и субтитры считаются по доле слов, а
  показывается всегда текст истории; расхождение больше 15 % рендер пишет
  предупреждением в отчёт.
- Встроенный голос macOS (`say`) читает ровно и без интонации: это черновик,
  чтобы увидеть монтаж. Живой голос — SpeechKit.
- Голос идёт через REST v3 SpeechKit (`tts/v3/utteranceSynthesis`) — у v1 нет
  голосов с амплуа (`alexander`, `anton`, `kirill`): на них он отвечает
  «Unsupported voice». Ответ v3 приходит потоком строк JSON, звук лежит кусками
  в `result.audioChunk.data` и склеивается по порядку.
- В SpeechKit рендер входит двумя способами: ключ `YC_API_KEY` и `YC_FOLDER_ID`
  из `.env.local` либо, если ключа нет, живая консоль `yc` (`yc iam
create-token` и `yc config get folder-id`). Ни токен, ни ключ в лог и в отчёт
  не печатаются. Один запрос берёт до 5000 знаков текста — история короче.
- Переозвучить готовую историю можно одной командой: карточки и клипы лежат в
  `out/reels/<id>/` с ключом в `cache.json` и заново не считаются, пересчёт идёт
  по звуку, словам и субтитрам. Меняется голос — меняются и длительности битов,
  поэтому клипы всё же перекодируются; браузер не запускается вовсе.
