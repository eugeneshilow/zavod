## 2026-09-20 13:28 · claude · ⚖️ reels-rail-playwright-ffmpeg · Ролики собирают Playwright и ffmpeg, файл всегда со звуком

**Решили.** Вертикальные ролики 1080×1920 собираются в этом же репозитории двумя рельсами с общей концовкой: серия слайдов (`content/reels/series/*.json` + лекало `content/reels/template.html`) и плакат из одной картинки (`content/reels/posters/*.json`). Кадры снимает Playwright (chromium) по HTML-лекалу, склеивает ffmpeg: кроссфейд 0.35 с, 30 кадров в секунду, H.264 `crf 20`, `yuv420p`, `+faststart`. Тайминг живёт в одном месте — `scripts/reels/lib.mjs`, длительность серии считается формулой `3 + N×3.4 + 3 − (N+1)×0.35`, её держит тест. Звуковая дорожка обязательна всегда: с флагом `--music` вшивается royalty-free трек из `assets/music/` с затуханием 1.5 с, без флага пишется тишина, и рендер помечает ролик как черновик. Каждый трек получает строку в `assets/music/LICENSES.md`. Готовые файлы ложатся в `out/`, он вне git. Канон — `docs/reels.md`.

**Отвергли.** Remotion — самый зрелый инструмент для анимации кодом, но платный за порогом трёх человек ($100/мес для машины, которая рендерит по расписанию); Playwright и ffmpeg бесплатны и ставятся одной командой. Ролик без аудиодорожки — Instagram такой файл не принимает, поэтому «без музыки» реализовано тишиной, а не отсутствием дорожки. Рисовать текст плаката через `drawtext` ffmpeg — шрифт пришлось бы искать файлом на диске; тот же текст в CSS даёт единый запасной шрифт с лекалом слайдов. Вшивать музыку из библиотеки Instagram — её лицензия действует только внутри продуктов Meta.

**Слова владельца.** «Задача: рельса сборки вертикальных роликов (1080×1920, 9:16) из HTML-слайдов и из одной картинки, без человека, в этом же репозитории.»
## 2026-09-20 13:22 · claude · ⚖️ reels-straight-to-instagram · Ролики едут в Instagram сами, рельсой из autovibecoding

**Решили.** Полный цикл публикации короткого видео живёт внутри проекта, а не в руках человека. Готовый файл заливается в хранилище Convex и встаёт в очередь `data_cooked_instagram_reels`; крон раз в 30 минут забирает один созревший ролик и публикует его через Graph API v23 (контейнер REELS, ожидание обработки, `media_publish`); крон раз в 6 часов приносит обратно просмотры, охват и реакции; крон раз в сутки продлевает токен. Рельса перенесена почти дословно из проекта `vibecoding-ru` (`convex/services/instagram.ts`, таблицы `data_*_instagram_*`, `workflows/instagram_publishing.ts`) — это работающий каркас, снятый целиком, а не написанный заново. Перед публикацией сходятся четыре замка: `INSTAGRAM_CRONS_ENABLED`, `INSTAGRAM_POSTING_ENABLED`, тумблер канала (по умолчанию выключен) и живой токен с непустой суточной квотой. Токен живёт только в таблице `ops_instagram_state` и наружу не отдаётся ни одним запросом. Статус видно на `/admin`: блок «Очередь Reels» и блок «Эфир», там же кнопка паузы канала. Иммунитет — `/api/reels/health` и почасовой сторож `reels-alive`. Канон зоны — `docs/publish.md`.

**Отвергли.** Три вещи. Публикацию руками по кнопке — владелец просил полный цикл, а не полуавтомат. Хранение токена в переменных окружения, как у остальных ключей, — токен живой, его продлевает крон, и переменная окружения такого не умеет. Публикацию с одной попытки: сеть моргнула — ролик пропал бы навсегда, поэтому первая и вторая неудача возвращают его в очередь со сдвигом на два часа, и только третья зажигает тревогу.

**Слова владельца.** «вези сразу всё в рилс — рельсы у нас уже есть внутри autovibecoding проекта, их перетащи в проект zavod-v6; делай сразу полный цикл — все ролики вези напрямую в инсту»

## 2026-09-19 21:40 · claude · ⚖️ go-online-github-vercel-convex · Проект живёт онлайн: приватный GitHub, Vercel, Convex в облаке

**Решили.** Код — в приватном репозитории `eugeneshilow/zavod-v6`; в `main` только слиянием pull request, и на каждый pull request и push в `main` GitHub Actions гоняет ту же `pnpm check`, что и человек. Хостинг — Vercel, привязанный к репозиторию: push в `main` собирает продакшен, pull request — превью; в продакшене сборка `pnpm check && npx convex deploy --cmd 'pnpm build'`, на превью `pnpm build`. База — Convex в облаке, деплои dev и продакшен; ключ продакшен-деплоя `CONVEX_DEPLOY_KEY` кладёт человек в Vercel сам. Иммунитет — почасовой `prod-alive` по адресу из `PROD_URL`. Канон — `docs/deploy.md`. Что человек делает дальше: создаёт deploy key в Convex и кладёт в Vercel; после слияния проверяет адрес продакшена и `/admin`.

**Отвергли.** Локальный бэкенд Convex — продакшену на Vercel не к чему подключаться. Публичный репозиторий — проект приватный, пока владелец не решит иначе. Сборка без проверки ради скорости — `/admin` показывал бы пустое стекло там, где статус нужнее всего.

**Слова владельца.** «Отвечай на языке этого промпта. Настрой Spec-Driven Company в этой папке со стеком Next.js и Convex и выведи проект онлайн: приватный репозиторий на GitHub, Vercel и Convex в облаке.»

## 2026-09-19 21:15 · claude · ⚖️ adopt-spec-driven-company · Истина живёт в docs, агенты исполняют, статус виден

**Решили.** Этот проект работает как Spec-Driven Company. Правила живут в `AGENTS.md`. Истина живёт в `docs/`: этот журнал — для решений, `README.md` — сводка на одну страницу, по файлу на зону — как что устроено. Агенты работают в worktree, пишут спеку раньше кода, запускают проверку перед каждым коммитом и останавливаются перед деньгами, ключами, персональными данными и всем, что публикуется наружу.

**Отвергли.** Держать истину в истории чата и в головах людей. Она не переживает новую сессию агента или нового человека.

**Слова владельца.** «Отвечай на языке этого промпта. Настрой Spec-Driven Company в этой папке со стеком Next.js и Convex и выведи проект онлайн: приватный репозиторий на GitHub, Vercel и Convex в облаке.»
