# Публикация сайта

## Требования и границы

Публичный сайт — https://eugeneshilow.github.io/zavod/, пульт — https://eugeneshilow.github.io/zavod/admin/. GitHub Pages раздаёт статические HTML, CSS и JavaScript. Документы и результат успешной проверки встраиваются при сборке; на сайте показана дата этой проверки. Данные демо и действия пользователя живут только в памяти вкладки. База, вход, генерация видео и публикация в соцсетях не подключаются.

Локальный режим сохраняет адрес /admin и чтение документов при запросе. Режим GitHub Pages использует префикс репозитория; конкретные параметры сборки живут в next.config.ts и workflow.

## Выпуск и наблюдение

Источник — main после слияния pull request. GitHub Actions проверяет проект, собирает статический сайт, проверяет HTML и пути ресурсов, загружает артефакт и публикует его через GitHub Pages. Pull request проходит ту же сборку без публикации. Ручной повтор доступен в Actions. Стекло публикации — workflow GitHub Pages в репозитории; результат проверки проекта также доступен во вкладке «Документы».

После каждого выпуска внешняя проверка запрашивает главную, пульт, CSS и JavaScript с публичного адреса. Неуспешный ответ, отсутствие ожидаемого содержимого или неправильный префикс ресурсов завершают workflow ошибкой. Это проверка в момент выпуска, не непрерывный мониторинг. При ошибке публикации смотрят упавший шаг в Actions и выпускают исправление через PR.

## План и приёмка

1. Включить готовую админку в main через PR, записать требования и решение.
2. Добавить статическую сборку для Pages, исправить внутреннюю ссылку и подпись снимка проверки.
3. Добавить workflow проверки, публикации и внешней проверки сайта.
4. Выполнить pnpm check, сборку и проверку файлов. Через PR включить изменение в main и опубликовать.
5. Убедиться, что публичные /zavod/ и /zavod/admin/ отвечают, стили и скрипты загружаются, поиск и вкладка документов работают в браузере.

Результат готов, когда сайт доступен по публичному адресу и workflow с внешней проверкой завершился успешно.
