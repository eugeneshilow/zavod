# Админка — executive summary завода и зеркало docs

Канон зоны: как устроена страница `/admin` и всё под ней прямо сейчас. Меняется заменой.

## Устройство

- **`/admin` — executive summary проекта.** Один экран, с которого читается всё: одна фраза «что это» из `docs/README.md`; три карточки пульса — публикация (очередь и двери), эфир Instagram (подписчики, последний пост), проверка и продакшен (результат `pnpm check`, коммит, адрес); карточки-двери в зоны; список решений из журнала. Подробности на этом экране не живут — за ними клик внутрь зоны.
- **Хедер — навигация на все экраны.** Чёрная полоса сверху, одна на всю админку: имя проекта слева ведёт на `/admin`, дальше по кнопке на зону; у зоны с подпапками кнопка ▾ открывает панель её поддерева. Справа — крошки пути. Под хедером шапка экрана: путь узла и подпись из заголовка канона, полоса «вверх · вниз» с дверями к родителю и прямым детям.
- **Дизайн снят с админки vibecoding.ru.** Светлая тема, один шрифт Inter, один оранжевый акцент, волосяные рамки вместо теней, таблицы плотности терминала: мелкий кегль, числа вправо, статус — словом или точкой, не бейджем. Карточка — только как дверь. Своего стиля админка не изобретает.

## Правило зеркала: адрес экрана = адрес канона

У каждой зоны проекта один файл канона в `docs/` и один экран в админке, и адреса у них совпадают:

| канон в docs                          | экран в админке          |
| ------------------------------------- | ------------------------ |
| `docs/admin.md`                       | `/admin`                 |
| `docs/reels.md`                       | `/admin/reels`           |
| `docs/publish.md`                     | `/admin/publish`         |
| `docs/research/README.md`             | `/admin/research`        |
| `docs/research/<срез>/README.md`      | `/admin/research/<срез>` |
| `docs/brains/README.md` (когда будет) | `/admin/brains`          |

Как это работает: хедер и дерево экранов строятся из папки `docs/` при каждом запросе (`lib/docs.ts`, `navTree`). Зона — файл `docs/<зона>.md` или папка `docs/<зона>/` с `README.md`; имя кнопки — имя файла или папки, подпись — первая строка файла без повтора имени: `docs/reels.md` с первой строкой `# reels — сборка вертикальных роликов` даёт кнопку «reels» и подпись «сборка вертикальных роликов», а `docs/deploy.md` с первой строкой `# Выход наружу — …` даёт кнопку «deploy» и подпись «Выход наружу — …». Служебные файлы папки — `README.md` и `journal.md` — зонами не считаются, но по адресу открываются (`/admin/journal`).

Экран без своего кода показывает канон зоны как есть (`app/admin/[...path]/page.tsx`); относительные ссылки между файлами docs становятся адресами экранов, так что по канону гуляют как по папкам. Зона, у которой есть живое стекло, получает свой файл раута рядом — он перекрывает общий: `app/admin/publish/page.tsx` сверху показывает очередь, двери и эфир, снизу тот же канон.

Что из этого следует: новый файл в `docs/` — новая кнопка в хедере и новый экран, без правки кода. Адрес, за которым нет файла, отвечает экраном «нет `docs/<путь>.md`»: ни один клик не ведёт в тупик, и тупик честно говорит, какого файла не хватает. Переименовал файл — переехал и экран; ссылки в других канонах чинятся там же.

## Доступ

`/admin` и всё под ним закрыто паролем `ADMIN_PASSWORD` (`proxy.ts`, basic auth). Пароль не задан — экраны открыты, а `/admin` вместо сводки говорит, что пароля нет. Действия (кнопки паузы дверей) идут в Convex с пропуском `ADMIN_API_TOKEN`; без него стекло публикации пишет причину вместо цифр.

## Известные края

- Дерево читается с диска при каждом запросе: на Vercel это файлы из сборки, значит новая зона появляется на продакшене после деплоя, а не после коммита.
- Картинки из docs (например, раскадровки в `docs/research/`) экран не показывает: сервер отдаёт только страницы, не файлы папки docs.
- Подпапки глубже двух уровней в дерево не входят; по адресу они всё равно открываются.
