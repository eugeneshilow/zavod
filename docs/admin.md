# Админка — executive summary завода и зеркало docs

Канон зоны: как устроена страница `/admin` и всё под ней прямо сейчас. Меняется заменой.

## Устройство

- **`/admin` — вход, а не сводка.** Один экран: фраза «что это» из `docs/README.md` и по карточке-двери на каждую зону из хедера с одной строкой пульса. Больше на нём ничего нет: цифры живут на экранах зон. Прежняя сводка из карточек пульса, четырёх зон и списка решений снята 21.09 по слову владельца («убери всё, что ты там наколотил»): её никто не просил.
- **Хедер — две кнопки, и это решение, а не автомат.** Чёрная полоса сверху, одна на всю админку: имя проекта слева ведёт на `/admin`, дальше по кнопке на зону из списка в разделе «Хедер» этого файла; у зоны с подпапками кнопка ▾ открывает панель её поддерева. Справа — крошки пути. Под хедером шапка экрана: путь узла и подпись из заголовка канона, полоса «вверх · вниз».
- **Дизайн снят с админки vibecoding.ru.** Светлая тема, один шрифт Inter, один оранжевый акцент, волосяные рамки вместо теней, таблицы плотности терминала: мелкий кегль, числа вправо, статус — словом или точкой, не бейджем. Карточка — только как дверь. Своего стиля админка не изобретает.

## Хедер

Что стоит кнопкой в хедере — решает этот список, не папка `docs/` целиком. Зона — папка `docs/<зона>/` с `README.md` или файл `docs/<зона>.md`; кнопка берёт имя папки, подпись — первую строку файла. Файл правил, которого в списке нет, экраном по адресу остаётся (`/admin/reels`, `/admin/publish`), но в хедер не лезет: каноны рельс читают агенты, а не владелец.

## Правило зеркала: адрес экрана = адрес канона

У каждой зоны проекта один файл канона в `docs/` и один экран в админке, и адреса у них совпадают:

| канон в docs                     | экран в админке          |
| -------------------------------- | ------------------------ |
| `docs/admin.md`                  | `/admin`                 |
| `docs/reels.md`                  | `/admin/reels`           |
| `docs/publish.md`                | `/admin/publish`         |
| `docs/research/README.md`        | `/admin/research`        |
| `docs/research/<срез>/README.md` | `/admin/research/<срез>` |
| `docs/brains/README.md`          | `/admin/brains`          |
| `docs/brains/<мозг>/README.md`   | `/admin/brains/<мозг>`   |
| `docs/social/README.md`          | `/admin/social`          |
| `docs/social/<сеть>.md`          | `/admin/social/<сеть>`   |
| `docs/brand/README.md`           | `/admin/brand`           |
| `docs/brand/layout.md`           | `/admin/brand/layout`    |
| `docs/brand/logo.md`             | `/admin/brand/logo`      |
| `docs/cabinet/README.md`         | `/admin/cabinet`         |
| `docs/customers/README.md`       | `/admin/customers`       |

Как это работает: адрес любого экрана — производная от пути файла (`lib/nav-tree.ts`, `hrefOf`), и обратно: адрес находит файл (`lib/docs.ts`, `resolveDoc`). Дерево хедера строится при каждом запросе из списка «Хедер» этого файла (`navTree`): для каждой зоны читается её файл или папка, подпапки становятся панелью ▾. Имя кнопки — имя папки или файла, подпись — первая строка файла без повтора имени: `docs/social/README.md` с первой строкой `# social — соцсети: аккаунты, двери, эфир по дням` даёт кнопку «social» и подпись «соцсети: аккаунты, двери, эфир по дням». Служебные файлы папки — `README.md` и `journal.md` — зонами не считаются, но по адресу открываются (`/admin/journal`).

Экран без своего кода показывает канон зоны как есть (`app/admin/[...path]/page.tsx`); относительные ссылки между файлами docs становятся адресами экранов, так что по канону гуляют как по папкам. Зона, у которой есть живое стекло, получает свой файл раута рядом — он перекрывает общий: `app/admin/publish/page.tsx` сверху показывает очередь, двери и эфир, снизу тот же канон. Так же устроены мозги и соцсети: `app/admin/social/page.tsx` — сводка сетей и эфир по дням, `app/admin/social/[network]/page.tsx` — одна сеть с кнопками ([social/README.md](social/README.md)); `app/admin/brains/page.tsx` — реестр (сводка и таблица по семьям, строка — мозг), `app/admin/brains/[brainId]/page.tsx` — профиль мозга (паспорт, рецепт, голова, приёмка, след прогонов), под каждым — его канон. Сами мозги читаются из папки `docs/brains/` ([brains/README.md](brains/README.md)): реестра в коде нет.

Что из этого следует: новый файл в `docs/` — новый экран по своему адресу без правки кода; кнопка в хедере — строка в списке «Хедер» выше, тоже без кода. Адрес, за которым нет файла, отвечает экраном «нет `docs/<путь>.md`»: ни один клик не ведёт в тупик, и тупик честно говорит, какого файла не хватает. Переименовал файл — переехал и экран; ссылки в других канонах чинятся там же.

## Доступ

`/admin`, `/cabinet` и весь хост `app.zavod.today` закрыты входом (`proxy.ts`). Без входа запрос уходит на страницу `/login` с адресом возврата; пароль — `ADMIN_PASSWORD`. После входа браузер получает куку `zavod_admin` на 90 дней: HttpOnly, Secure, SameSite=Lax, домен `.zavod.today`, поэтому один вход действует и на zavod.today, и на app.zavod.today. Кука — срок и подпись HMAC-SHA256 этого срока ключом `ADMIN_PASSWORD`: сменили пароль — все входы разом погасли. Когда до конца срока меньше 30 дней, заход продлевает вход ещё на 90 (`lib/admin-session.ts`). Выход — `/logout`, кнопка «Выйти» в кабинете. Заголовок Basic с тем же паролем принимается тоже — для скриптов, скриншотов и тестов. Запрос без входа, который не GET (кнопки форм), получает 401 без переадресации. Пароль не задан — экраны открыты, а `/admin` вместо сводки говорит, что пароля нет (⚖️ admin-session-90d, [journal.md](journal.md)). Действия (пауза двери, прогон очереди и снятие цифр «сейчас») идут в Convex с пропуском `ADMIN_API_TOKEN`; без него экраны пишут причину вместо цифр.

## Известные края

- Дерево читается с диска при каждом запросе: на Vercel это файлы из сборки, значит новая зона появляется на продакшене после деплоя, а не после коммита.
- Картинки из docs (например, раскадровки в `docs/research/`) экран не показывает: сервер отдаёт только страницы, не файлы папки docs.
- Подпапки глубже двух уровней в дерево не входят; по адресу они всё равно открываются.
