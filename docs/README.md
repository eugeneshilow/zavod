# zavod

Дата: 2026-09-13. Локальная основа проекта по принципам Spec-Driven Company.

## Что это

zavod — локальная основа приложения, в которой требования и решения живут в документах, а состояние проверок видно на странице управления.
Она предназначена для владельца проекта и работающих с ним агентов; продуктовые функции пока не заданы.
Готовность основы: главная и `/admin` отвечают, журнал показывает первое решение, `pnpm check` проходит, незаполненных шаблонов нет.

## Решения

Решения и их причины хранятся в [журнале](journal.md), новые сверху:

- ⚖️ adopt-spec-driven-company — документы задают правила, агенты исполняют их, состояние видно без вопросов.
- ⚖️ convex-without-login — подготовить Convex; подключение облачной базы выполняет владелец, когда она понадобится.

## Где что лежит

- `docs/` — эта страница и [журнал решений](journal.md); `INDEX.md` и `DECISIONS.md` — флотские индексы, получаемые из файлов.
- `AGENTS.md` — правила работы; раздел «Стек» содержит состав, команды проверки и запуска. `CODEX.md` и `CLAUDE.md` дополняют их для конкретного агента.
- `src/` — страницы и чтение файлов; `scripts/` — запуск проверки; `convex/schema.ts` — пустая схема будущей базы.
- `.env.local.example` — пустые имена переменных Convex. Настоящие значения CLI запишет в `.env.local`; этот файл никогда не коммитится.

## Зоны

Сначала создаётся каркас Next.js с TypeScript, Tailwind CSS и App Router, затем проверка, страницы, тест и подготовка Convex. Отдельные документы зон появятся вместе с их первым правилом.

Главная берёт название и первое предложение описания из этой страницы и ведёт на `/admin`. Страница управления читает этот документ и журнал при запросе, показывает их как HTML и отдельно перечисляет все решения по заголовкам с ⚖️. Оформление простое, с системным шрифтом и без шаблонных иллюстраций.

Convex подключается через клиентский провайдер только при непустой `NEXT_PUBLIC_CONVEX_URL`. Серверные функции появятся после подключения базы. Следующий шаг владельца при необходимости базы: запустить `npx convex dev` в корне и войти в аккаунт. Vercel выбран как будущая площадка; публикация в эту настройку не входит.

## Состояние

[Главная](http://localhost:3000) и [управление](http://localhost:3000/admin) запускаются локально. `/admin` показывает результат последнего `pnpm check` и время в МСК из игнорируемого `.check-result.json`. Проверка последовательно запускает Prettier, ESLint, генерацию типов маршрутов Next.js, TypeScript и Vitest; при ошибке сохраняет красный результат и возвращает ненулевой код. Живой статус хранится в файле, а не в документации.
