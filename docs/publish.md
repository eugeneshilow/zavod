# Публикация — очередь, две двери, эфир, метрики

Канон зоны: как готовый ролик или картинка попадает в Instagram и в Telegram
сам, без человека в цикле. Меняется заменой.

## Устройство

Одна очередь, две двери. Файл попадает в хранилище Convex, встаёт в очередь по
строке на каждую дверь, один крон забирает по материалу на дверь и публикует,
второй крон приносит обратно цифры Instagram. Очередь везёт два вида материала:
вертикальный ролик (Reels) и одиночную картинку; вид хранится в поле
`mediaType`, по умолчанию ролик. Дверь хранится в поле `channel`: `instagram`
или `telegram`; поля нет — значит `instagram`.

1. **Вход.** Файл `.mp4` (ролик) или `.png`/`.jpg` (картинка) заливается в
   хранилище Convex (`workflows/instagram_publishing:generateUploadUrl` отдаёт
   одноразовый адрес, файл уходит туда обычным POST). Обёртка —
   `scripts/reels/publish.mjs`: файл, подпись, вид (`--type image` или
   `--type reels`, по умолчанию ролик), двери (`--to instagram|telegram|all`,
   по умолчанию обе), время публикации.
2. **Очередь.** `tables/data_cooked_instagram_reels:enqueueFromStorage` кладёт
   строку со статусом `approved`, дверью, подписью и плановым временем
   `scheduledAt`. Файл заливается один раз на все двери, плановое время у строк
   общее. Источник файла ровно один: либо публичный адрес `videoUrl`, либо
   `storageId` в хранилище — не оба сразу и не ни одного. Один и тот же
   `storageId` дважды в одну дверь не встаёт: повтор команды не родит второй
   пост. В разные двери один файл встаёт двумя строками — это и есть
   кросспостинг.
3. **Публикация.** Крон `instagram-run-queue` раз в 30 минут обслуживает обе
   двери по очереди: сначала Instagram, потом Telegram, и публикует не больше
   одного материала на дверь. Дверь берёт самый старый созревший `approved`
   своего канала, переводит его в `posting`, публикует и записывает `mediaId` и
   `permalink`.
   - **Instagram.** Контейнер в Graph API v23, ожидание готовности (18 попыток
     по 15 секунд), `media_publish`. Ролик едет как `media_type=REELS` с полем
     `video_url`; картинка — как `image_url`, поле `media_type` у неё не
     передаётся вовсе.
   - **Telegram.** Один запрос Bot API: ролик — `sendVideo` с
     `supports_streaming=true`, картинка — `sendPhoto`; файл Telegram
     выкачивает сам по адресу хранилища. `mediaId` строки — номер сообщения,
     `permalink` — `https://t.me/<канал>/<номер>`.
4. **Метрики.** Крон `instagram-collect-metrics` раз в 6 часов читает последние
   медиа аккаунта Instagram (ловит и ручные публикации), пишет их в реестр и
   добавляет новую точку в серию цифр. Раз в сутки крон
   `instagram-refresh-token` продлевает токен Instagram. Двери Telegram эти два
   крона не касаются.

## Куда пишет

| Таблица                       | Что держит                                                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data_cooked_instagram_reels` | очередь обеих дверей: дверь (`channel`), подпись, вид (`REELS` или `IMAGE`), источник файла, статус, план, попытки, ошибка, `mediaId`, `permalink` |
| `data_raw_instagram_media`    | реестр опубликованных медиа Instagram; факт записывается один раз и не переписывается                                                              |
| `data_raw_instagram_metrics`  | серия цифр по каждому медиа Instagram: новая точка на каждый сбор, старые не трогаются                                                             |
| `ops_instagram_state`         | дом токена Instagram: сам токен, id аккаунта, срок жизни, время последнего прогона очереди                                                         |
| `ops_channel_toggles`         | пауза и включение двери: событие с причиной, состояние — последнее событие; у каждой двери своё                                                    |
| `ops_alerts`                  | что сломалось: пост не ушёл, очередь протухла, рефреш токена упал                                                                                  |
| `ops_social_snapshots`        | дневной снимок аккаунта Instagram: подписчики, расход суточного лимита                                                                             |

Статусы очереди: `draft` → `approved` → `posting` → `posted`; мимо — `failed`
(три неудачи подряд) и `skipped` (гейт свежести).

## Гейты: что должно совпасть, чтобы пост ушёл

Публикация — необратимое действие наружу, поэтому перед ней сходятся замки.
Любой закрыт — прогон молча ничего не делает и говорит почему.

Общие для обеих дверей:

1. `INSTAGRAM_CRONS_ENABLED=true` в Convex — иначе кронов вообще нет в
   расписании.
2. `INSTAGRAM_POSTING_ENABLED=true` в Convex — общий рубильник публикации (имя
   историческое: он появился раньше второй двери и глушит обе). Кроны крутятся,
   посты не уходят.

Свои у каждой двери:

3. Тумблер двери в `ops_channel_toggles`: `instagram` и `telegram` включаются
   отдельно. По умолчанию обе выключены: пока человек не нажал кнопку на
   `/admin`, машина не постит.
4. Instagram: в `ops_instagram_state` лежит живой токен, и суточная квота
   Instagram (100 публикаций через API на аккаунт за 24 часа) не исчерпана.
5. Telegram: в переменных Convex лежат оба имени — `TELEGRAM_BOT_TOKEN` и
   `TELEGRAM_CHAT_ID`.

## Вне очереди

Показать ролик сегодня, а не по плану: плановое время строки переносится на
«сейчас», статус остаётся `approved`, и ближайший тик забирает её первой. Тик
можно не ждать — прогнать очередь руками. Крон и ручной прогон публикуют не
больше одного материала на дверь, поэтому на два ролика — два прогона.

```
npx convex run tables/data_cooked_instagram_reels:publishNow '{"ids":["<id строки>","<id строки>"]}' --prod
npx convex run workflows/instagram_publishing:runQueue '{}' --prod
```

Id строк — колонка `_id` в `npx convex data data_cooked_instagram_reels --prod`
или блок «Очередь» на `/admin`. Гейты те же, что у крона: рубильники, тумблер
двери, ключи. Строки не в `approved` команда пропускает и называет.

## Повтор после сбоя

Сеть моргнула, Meta ответила пятисоткой — ролик не выбрасывается. Первая и
вторая неудача возвращают строку в `approved` и сдвигают план на два часа
вперёд; счётчик попыток растёт. Третья неудача переводит строку в `failed` и
роняет запись в `ops_alerts`: дальше нужен человек. Правило одно на обе двери, и
строки разных дверей падают независимо: не уехало в Telegram — пост в Instagram
уже в эфире и не повторяется.

Отдельно работает гейт свежести. Материал, пролежавший в очереди дольше 48 часов
от планового времени, уже не новость: он уходит в `skipped` с одной общей
записью в `ops_alerts`, а не публикуется задним числом.

## Где живут ключи

Значения не проходят через чат и не лежат в файлах. В репозитории — только
имена, в `.env.local.example`.

- **Токен Instagram** живёт в таблице `ops_instagram_state`, не в переменных
  окружения: он протухает за 60 дней, и его продлевает крон. Пишет его человек
  одной командой `npx convex run` (ниже); наружу его не отдаёт ни один запрос —
  читают только внутренние функции.
- **Токен Telegram** живёт в переменных Convex: у Bot API он не протухает,
  продлевать нечего, поэтому таблица ему не нужна. В текст ошибки он не попадает
  — сервис вырезает его перед записью в очередь.
- **Convex (продакшен)**: `INSTAGRAM_CRONS_ENABLED`, `INSTAGRAM_POSTING_ENABLED`,
  `ADMIN_API_TOKEN`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
- **Vercel (production)**: `ADMIN_API_TOKEN` — тем же значением, что в Convex.
  Этим токеном страница `/admin` и проверка `/api/reels/health` спрашивают у
  Convex очередь и эфир.
- Локально те же имена — в `main/.env.local`.

Команды для человека, по порядку. Выполняются из `main/`, значения человек
подставляет сам.

```
npx convex env set ADMIN_API_TOKEN <значение> --prod
npx convex env set INSTAGRAM_POSTING_ENABLED false --prod
npx convex env set INSTAGRAM_CRONS_ENABLED true --prod
npx convex run tables/ops_instagram_state:set '{"accessToken":"<long-lived токен>","igUserId":"<id>","expiresAt":<мс>}' --prod
npx convex env set TELEGRAM_BOT_TOKEN <значение от @BotFather> --prod
npx convex env set TELEGRAM_CHAT_ID @autovibecoding --prod
```

Бот должен быть администратором канала `@autovibecoding` с правом публикации —
иначе Telegram ответит `chat not found` или `not enough rights`.

Очередь, написанная до второй двери, не видна индексу по каналу. Один раз, после
первого деплоя с этой правкой, человек проставляет старым строкам дверь:

```
npx convex run tables/data_cooked_instagram_reels:backfillChannel '{}' --prod
```

То же значение `ADMIN_API_TOKEN` кладётся в Vercel → Settings → Environment
Variables (Production). Когда очередь проверена на одном ролике,
`INSTAGRAM_POSTING_ENABLED` переводится в `true`.

## Стекло

Страница `/admin` (за паролем) несёт два блока сверху:

- **Очередь Reels** — строки очереди: статус, дверь, вид (ролик или картинка),
  подпись, план и факт, число попыток, текст ошибки. У опубликованной строки
  время факта — ссылка на сам пост, и для Instagram, и для Telegram.
- **Эфир** — опубликованные медиа Instagram: ссылка, просмотры, охват, лайки,
  комментарии, сохранения, репосты, прирост за 24 и 48 часов по снимкам, число
  подписчиков и расход суточной квоты. Telegram в этом блоке не появляется.

Там же кнопка паузы — своя на каждую дверь: она пишет событие в
`ops_channel_toggles` с причиной. Пауза действует мгновенно — следующий прогон
крона её увидит.

## Иммунитет

`/api/reels/health` отдаёт
`{queue:{approved,…}, byChannel:{instagram:{…}, telegram:{…}}, lastRunAt, cronsEnabled}`
— счётчики всей очереди, те же счётчики в разрезе дверей и время последнего
прогона, без секретов. `.github/workflows/reels-alive.yml` раз в 6 часов
запрашивает этот адрес на продакшене и падает, если ответ не 200 или если в
очереди есть хоть один `failed`. Проверка техническая: она молчит, когда очередь
пуста, и кричит, когда материал не смог уехать.

## Известные края

- Instagram и Telegram выкачивают файл сами по адресу из хранилища Convex.
  Адрес должен быть доступен снаружи; локальный dev-деплой для публикации не
  годится.
- Telegram по адресу забирает файл не больше 20 МБ (и 10 МБ для картинки). Наши
  ролики весят 1–2 МБ, но длинный файл дверь не увезёт: ответ будет
  `failed to get HTTP URL content`.
- Подпись в Telegram ограничена 1024 символами; длиннее — сервис обрезает её и
  ставит многоточие, а не роняет публикацию.
- Цифры по каналу Telegram машина не собирает: Bot API не отдаёт ни просмотров
  поста, ни охвата. Смотреть их можно только руками в самом канале.
- Обработка видео на стороне Meta занимает до нескольких минут. Прогон ждёт
  максимум 4,5 минуты (18 × 15 с); если не успело — попытка считается неудачной
  и материал вернётся через два часа. Картинка готова заметно быстрее, но ждёт
  по тем же правилам.
- Insights по свежему рилу приходят не сразу: первые часы метрики могут быть
  пустыми, и это не поломка.
- Токен Instagram живёт 60 дней и продлевается кроном, но только если он старше
  суток и ещё жив. Токен, умерший совсем, кроном не воскрешается: нужен новый
  вход через Instagram business login и повторная запись в
  `ops_instagram_state`.
- Квота Instagram — 100 публикаций через API за 24 часа на аккаунт. Прогон
  проверяет её до публикации и пропускает ход, если она выбрана.
- Кроны читают `INSTAGRAM_CRONS_ENABLED` в момент деплоя Convex, а не на каждом
  тике: смена переменной вступает в силу после следующего деплоя.
