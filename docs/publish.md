# Публикация в Instagram — очередь Reels, эфир, метрики

Канон зоны: как готовый ролик попадает в Instagram сам, без человека в цикле. Меняется заменой.

## Устройство

Один путь, четыре шага. Ролик попадает в хранилище Convex, встаёт в очередь, крон забирает его и публикует, второй крон приносит обратно цифры.

1. **Вход.** Файл `.mp4` заливается в хранилище Convex (`workflows/instagram_publishing:generateUploadUrl` отдаёт одноразовый адрес, файл уходит туда обычным POST). Обёртка — `scripts/reels/publish.mjs`: файл, подпись, время публикации.
2. **Очередь.** `tables/data_cooked_instagram_reels:enqueueFromStorage` кладёт строку со статусом `approved`, подписью и плановым временем `scheduledAt`. Источник видео ровно один: либо публичный адрес `videoUrl`, либо `storageId` в хранилище — не оба сразу и не ни одного. Один и тот же `storageId` дважды в очередь не встаёт: повтор команды не родит второй пост.
3. **Публикация.** Крон `instagram-run-queue` раз в 30 минут забирает самый старый созревший `approved`, переводит его в `posting`, создаёт REELS-контейнер в Graph API v23, ждёт обработки видео (18 попыток по 15 секунд), публикует и записывает `mediaId` и `permalink`. За один прогон публикуется не больше одного ролика.
4. **Метрики.** Крон `instagram-collect-metrics` раз в 6 часов читает последние медиа аккаунта (ловит и ручные публикации), пишет их в реестр и добавляет новую точку в серию цифр. Раз в сутки крон `instagram-refresh-token` продлевает токен.

## Куда пишет

| Таблица                       | Что держит                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------- |
| `data_cooked_instagram_reels` | очередь: подпись, источник видео, статус, план, попытки, ошибка, `mediaId`, `permalink` |
| `data_raw_instagram_media`    | реестр опубликованных медиа; факт записывается один раз и не переписывается             |
| `data_raw_instagram_metrics`  | серия цифр по каждому медиа: новая точка на каждый сбор, старые не трогаются            |
| `ops_instagram_state`         | дом токена: сам токен, id аккаунта, срок жизни, время последнего прогона очереди        |
| `ops_channel_toggles`         | пауза и включение канала: событие с причиной, состояние — последнее событие             |
| `ops_alerts`                  | что сломалось: пост не ушёл, очередь протухла, рефреш токена упал                       |
| `ops_social_snapshots`        | дневной снимок аккаунта: подписчики, расход суточного лимита                            |

Статусы очереди: `draft` → `approved` → `posting` → `posted`; мимо — `failed` (три неудачи подряд) и `skipped` (гейт свежести).

## Гейты: что должно совпасть, чтобы пост ушёл

Публикация — необратимое действие наружу, поэтому перед ней сходятся четыре замка. Любой закрыт — прогон молча ничего не делает и говорит почему.

1. `INSTAGRAM_CRONS_ENABLED=true` в Convex — иначе кронов вообще нет в расписании.
2. `INSTAGRAM_POSTING_ENABLED=true` в Convex — аварийный рубильник; кроны крутятся, посты не уходят.
3. Тумблер канала `instagram` включён (`ops_channel_toggles`). По умолчанию канал выключен: пока человек не нажал кнопку на `/admin`, машина не постит.
4. В `ops_instagram_state` лежит живой токен, и суточная квота Instagram (100 публикаций через API на аккаунт за 24 часа) не исчерпана.

## Повтор после сбоя

Сеть моргнула, Meta ответила пятисоткой — ролик не выбрасывается. Первая и вторая неудача возвращают строку в `approved` и сдвигают план на два часа вперёд; счётчик попыток растёт. Третья неудача переводит строку в `failed` и роняет запись в `ops_alerts`: дальше нужен человек.

Отдельно работает гейт свежести. Ролик, пролежавший в очереди дольше 48 часов от планового времени, уже не новость: он уходит в `skipped` с одной общей записью в `ops_alerts`, а не публикуется задним числом.

## Где живут ключи

Значения не проходят через чат и не лежат в файлах. В репозитории — только имена, в `.env.local.example`.

- **Токен Instagram** живёт в таблице `ops_instagram_state`, не в переменных окружения. Пишет его человек одной командой `npx convex run` (ниже); наружу его не отдаёт ни один запрос — читают только внутренние функции.
- **Convex (продакшен)**: `INSTAGRAM_CRONS_ENABLED`, `INSTAGRAM_POSTING_ENABLED`, `ADMIN_API_TOKEN`.
- **Vercel (production)**: `ADMIN_API_TOKEN` — тем же значением, что в Convex. Этим токеном страница `/admin` и проверка `/api/reels/health` спрашивают у Convex очередь и эфир.
- Локально те же имена — в `main/.env.local`.

Команды для человека, по порядку. Выполняются из `main/`, значения человек подставляет сам.

```
npx convex env set ADMIN_API_TOKEN <значение> --prod
npx convex env set INSTAGRAM_POSTING_ENABLED false --prod
npx convex env set INSTAGRAM_CRONS_ENABLED true --prod
npx convex run tables/ops_instagram_state:set '{"accessToken":"<long-lived токен>","igUserId":"<id>","expiresAt":<мс>}' --prod
```

То же значение `ADMIN_API_TOKEN` кладётся в Vercel → Settings → Environment Variables (Production). Когда очередь проверена на одном ролике, `INSTAGRAM_POSTING_ENABLED` переводится в `true`.

## Стекло

Страница `/admin` (за паролем) несёт два блока сверху:

- **Очередь Reels** — строки очереди: статус, подпись, план и факт, число попыток, текст ошибки.
- **Эфир** — опубликованные медиа: ссылка, просмотры, охват, лайки, комментарии, сохранения, репосты, прирост за 24 и 48 часов по снимкам, число подписчиков и расход суточной квоты.

Там же кнопка паузы канала: она пишет событие в `ops_channel_toggles` с причиной. Пауза действует мгновенно — следующий прогон крона её увидит.

## Иммунитет

`/api/reels/health` отдаёт `{queue:{approved,posted,failed}, lastRunAt, cronsEnabled}` — счётчики и время последнего прогона, без секретов. `.github/workflows/reels-alive.yml` раз в 6 часов запрашивает этот адрес на продакшене и падает, если ответ не 200 или если в очереди есть хоть один `failed`. Проверка техническая: она молчит, когда очередь пуста, и кричит, когда ролик не смог уехать.

## Известные края

- Meta выкачивает видео сама по адресу из хранилища Convex. Адрес должен быть доступен снаружи; локальный dev-деплой для публикации не годится.
- Обработка видео на стороне Meta занимает до нескольких минут. Прогон ждёт максимум 4,5 минуты (18 × 15 с); если не успело — попытка считается неудачной и ролик вернётся через два часа.
- Insights по свежему рилу приходят не сразу: первые часы метрики могут быть пустыми, и это не поломка.
- Токен живёт 60 дней и продлевается кроном, но только если он старше суток и ещё жив. Токен, умерший совсем, кроном не воскрешается: нужен новый вход через Instagram business login и повторная запись в `ops_instagram_state`.
- Квота — 100 публикаций через API за 24 часа на аккаунт. Прогон проверяет её до публикации и пропускает ход, если она выбрана.
- Кроны читают `INSTAGRAM_CRONS_ENABLED` в момент деплоя Convex, а не на каждом тике: смена переменной вступает в силу после следующего деплоя.
